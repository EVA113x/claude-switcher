## 🔧 核心改进

### 问题根因
1. **安装器**: 优先检查配置目录而非实际运行进程
   - 旧 Clash 目录存在 → 误识别为 clash-verge
   - 即使只运行 Shadowrocket

2. **保镖同步**: 核心脚本与 root 守护脚本不一致
   - `set-client` 只更新用户脚本
   - 无法自动同步 `/Library/.../claude-bodyguard.sh`

### 解决方案

#### 1. 安装器三级优先级
```
优先级 1: CLAUDE_PROXY_CLIENT 环境变量强制指定
优先级 2: 实际运行的进程(pgrep/scutil)  ← 新增
优先级 3: 配置目录存在
优先级 4: 手动选择
```

**效果**: 运行中的 Shadowrocket 优先于残留的 Clash 目录

#### 2. set-client 新增 --sync
```bash
# 旧行为(仍兼容)
claude-switch.sh set-client shadowrocket

# 新功能: 同时同步 root 保镖
claude-switch.sh set-client shadowrocket --sync
```

**效果**: 无需重新运行完整安装器即可同步保镖

```bash

cd ~/Downloads && tar -xzf shadowrocket-fix-deployment.tar.gz

```

### 方法 B: 更新核心 + 同步保镖(已安装用户)
```bash
cp ~/Downloads/.../core/claude-switch.sh ~/.local/bin/
chmod +x ~/.local/bin/claude-switch.sh
~/.local/bin/claude-switch.sh set-client shadowrocket --sync
```
